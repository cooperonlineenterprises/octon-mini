# Optional Architecture Proof Family

Authority: `SRC-DEC-0005`. These source-only assets are never generated by a
profile and never establish permission, adoption, approval, or production
readiness.

Use an Architecture Proof only when a consequential decision has material
uncertainty, a risky dependency or provider, an external-effect boundary, a
large rationale package, or potential promotion into shared Blueprint
guidance. Routine reversible work should use ordinary tasks and evidence.

The five proof kinds share one schema:

- `spike` — test a bounded feasibility hypothesis;
- `reference_slice` — exercise a minimal end-to-end architecture slice;
- `provider_qualification` — test an exact provider/version/configuration;
- `adversarial_fixture_pack` — concentrate failure and abuse cases; and
- `readiness_evidence` — gather bounded evidence for a separately owned gate.

Copy the closest file from `templates/`, assign a real `PROOF-####` ID, replace
every unassessed field from direct evidence, and validate against
`schema.json`. A completed proof may conclude `supported`, `unsupported`, or
`inconclusive`. Failed and inconclusive outcomes are valid evidence when they
truthfully preserve the method, failures, skips, cleanup, and limitations.

Template completion proves nothing. A `readiness_evidence` record still
cannot accept a gate or establish project readiness without the current
project-owned criteria, authority, exact subject, and evidence.
